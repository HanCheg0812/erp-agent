## 当前实现

案件搜索与状态筛选、列表/详情切换、全部方案动作的变更对比、证据定位引用、审计活动、审批/驳回及备注、新建案件、列表 JSON 导出、登录与退出已实现。

主界面为左侧案件会话列表、中央 Chat 消息和底部输入框。Agent 回复内展示可折叠步骤、Read order / Search evidence 工具操作及方案；展开后显示函数名、ERPNext / OpenViking 来源与结果，主界面不附加 MCP 后缀。审批/驳回直接附着于方案。点击来源、订单或活动打开右侧抽屉；原节点图作为 Execution details 保留，包含 JCode、工具依赖、人工审批与未发送的 ERP 执行。旧节点图优先版本另保存在 `opendesign/mockups/forge-node-flow/`。

目标是 JCode 的模型 → 工具 → 结果写回 → 下一轮模型循环；一个模型响应也可能发出多个工具调用。UI 的合成动画仍按定时脚本推进，不是接通的 loop，也不规定生产调用次数和顺序。演示在读取订单后单独展示已知结果和检索依据的任务更新，再进入知识工具阶段。消息滚动区底部采用 44px 透明渐隐，末尾额外留白以确保最后的审批或回复能完整滚入可读区域，输入框本身不透明。

输入框支持发送、换行及中文 IME；模拟分析时可暂停、恢复和重播。输入的证据/订单/状态问题使用当前合成案件的固定回复，不是实时模型生成；任意消息不会改写固定方案。每案消息和草稿切换后保留于页面内存，登录/退出切换会话范围时清空。证据抽屉呈现合成文档摘录或已存定位引用，不伪装成已读取原件。

合成案例支持播放、暂停、继续和重播。ATLAS 使用明确的订单变更（非预测需求），首次播放后产生案件/方案 v2，审批后为案件 v3；重播不重复生成方案、审批或业务事件。已有方案可重播模拟过程；未配置样例的新案件不生成虚构的 ERP 基线。已登录模式不会根据案件状态推断 Agent 运行完成，只显示尚未接入运行时。

`search_case_knowledge` 是拟定的业务网关工具名，不是声称已接入的 OpenViking 原生 schema。目标链路为 JCode → 受控 stdio MCP 网关 → 权限适配 → OpenViking HTTP MCP。当前浏览器只读取合成 fixture，界面标明 Simulation / No external calls；证据摘录、URI 和工具结果均为演示，未读取本机 ERP 或知识库。

演示模式明确显示 Demo data，使用合成民品案例，操作仅保存在本次页面内存，刷新会重置。审批后记录状态、版本、备注和活动，不能重复决策，不代表 ERP 执行。

API 客户端连接身份、案件、审批及审计接口。登录后加载真实案件 ID 与角色；错误明确展示，不能静默回退演示。审批携带方案 digest、案件版本及重试幂等键；权限和业务校验仍由后端负责。浏览器只收到业务登录令牌，不接触 ERP 或 Cube 凭据。

开发入口：`http://127.0.0.1:4173/`，`/v1` 代理到本地 3100 端口。OpenDesign 入口：`http://127.0.0.1:8289/`，仅服务 `opendesign/` 目录并绑定回环地址。`npm run preview:build` 将同一份 Web 构建产物复制到预览目录，避免两个界面分叉。静态预览使用演示数据；真实连接需要 API 代理或配置 API base。
