# 工具授权与业务审批

2026-09-22，用户确认两类都需要。后端与运行时已实现，本机集成检查通过；真实 ERP 写入仍未接入。

此前三模式只接入 `memory_save` 是本项目实现缺口，不是 JCode 的限制。固定上游的 `request_permission` 仅注册到 ambient；业务运行路径采用 PostgreSQL 挂起/恢复，不能直接使用上游文件队列。

本次范围：

- 将工具授权入口统一用于 `memory_save`、`case_set_context`、`proposal_create`。读取按原有账户范围执行。ask 等待用户、auto 独立审核、full 直接执行；都不能扩大账户权限。
- `request_proposal_approval` 绑定已保存提案 ID、摘要和案件版本，展示具体变更，等待有 approver 角色的用户通过已有业务审批接口决定。三模式不替代业务签字。
- 案件信息可在对话中补齐，不增加新会话表单；`case_read` 每次读取最新记录及当前案件文档元数据。
- 授权、业务写入和工具结果同一事务；重复恢复不重复创建。版本过期、拒绝、取消、跨账户、无角色均拒绝；审批不发送 ERP 写入。
- 当前服务固定到 `.runtime/releases/` 的二进制，隔离验证后再整体切换 API 与 Runtime。

验证：Rust/PostgreSQL 隔离测试覆盖权限、版本、并发幂等和重启；真实模型从补齐信息到创建提案、请求业务审批、决定后续跑；桌面/手机卡片可见，页面无运行错误。
