# Business Web

React 19/Vite case conversations for the Rust business API. Unauthenticated visitors see the sign-in page with email/password registration. After authentication, the workspace presents the case list, conversation, inline tool calls, and proposals with approval controls. New accounts start with empty cases and personal memory, with a direct action to create their first case.

Synthetic cases are available only through **View demo** on the authentication page. The demo has visible **Sign in** and **Leave demo** controls. Search, status filters, case creation, proposal review, evidence references, activity, approval/rejection comments, and JSON export are available. Demo changes stay in browser memory and reset on reload. Approval never executes ERP changes.

The conversation references Astryx's ChatLayout, ChatToolCalls, ChatReasoning and artifact-panel patterns, implemented with local React components. Analysis steps collapse into a summary, Read order / Search evidence operations expand to show the tool name, source and result, and evidence/order/activity open in a side drawer. MCP protocol names are not primary labels. The original node graph is secondary execution detail. The previous graph-first build is preserved at `opendesign/mockups/forge-node-flow/`.

Demo runs can pause, resume, and replay. The Atlas order fixture creates one proposal; replays do not duplicate it or approvals. Demo replies are canned, with messages and drafts retained in page memory. Authenticated conversations instead use PostgreSQL persistence and the JCode Rust Loop when the project model service is configured. Streaming output, tool activity, interruption and context compression are connected to persisted run events. Infrastructure status is not shown as a business-chat banner.

Demo tool results and evidence are fixtures. Live cases support controlled case reads, todo and Skill discovery/loading; ERPNext tools, actual document parsing and scoped OpenViking retrieval remain pending. The intended knowledge integration is JCode -> controlled stdio MCP gateway -> knowledge authorization adapter -> OpenViking. Document originals are stored privately in RustFS, with downloads authorized by the Rust API.

Registration and login use the Rust authentication endpoints; the client cannot choose tenant, owner or roles. The returned bearer token is stored in local storage. Refresh restores a valid session. Logout revokes the server token, clears local state and returns all open tabs to sign-in. An authenticated HTTP 401 clears the expired session; a transient API failure retains the session and offers Retry. Account changes unmount the previous workspace. Approval requests include the proposal digest, expected case version, and an idempotency key retained for retries of the same input. Backend authorization and state checks remain authoritative. Email verification and password recovery are not implemented yet.

Run from the repository root with `npm run dev:web` and open `http://127.0.0.1:4173`. Vite proxies `/v1` to the local business API at `http://127.0.0.1:3100`; `VITE_API_URL` can override the API base. Start the API separately using the root README. No runtime sockets, Cube administration, or enterprise credentials are exposed to the browser.

`npm run build:web` type-checks and builds the app. `npm run preview:build` also copies that build into the OpenDesign preview and refreshes its manifest. The standalone static preview supports the demo; authenticated use requires an API proxy or configured API base.

The visual language references Astryx, with local React/Lucide components and a strictly grayscale palette. Astryx is not a runtime dependency. See [Web validation and remaining scope](../../docs/plantree/plans/server-demo/web-ui.md) for observed checks and pending integration work.

Run `node scripts/verify-web-auth.mjs` with a local Playwright installation and Chrome, or set `PLAYWRIGHT_MODULE` and `CHROME_PATH`. The check creates synthetic personal accounts and one case against the running Rust API, verifies registration, login persistence, cross-tab logout, expiry, transient failure recovery and account isolation, and writes screenshots plus a report to `/tmp/erp-auth-entry` (override with `VERIFY_AUTH_OUTPUT`). It makes no model or ERP calls. Latest authentication acceptance is recorded in [Rust/auth verification](../../docs/plantree/plans/server-demo/rust-auth-context.md).
